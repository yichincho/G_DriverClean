Google 雲端硬碟與 Gmail 登入操作 — 一步一步教學

為了確保您的 Google 帳號密碼與雲端檔案完全掌握在自己手中，本工具不經過中介伺服器，只需 5 分鐘設定您專屬的免費 OAuth 2.0 憑證即可登入。

完全免費且無須信用卡

提示：Client ID 會安全地儲存在您的本機瀏覽器 localStorage 中，重新整理頁面後不需重複輸入。

步驟 01

透過本地伺服器開啟本網頁（http://localhost:8080）

Google 安全政策禁止從 file:// 本機路徑發起 OAuth 登入。請在資料夾 c:\AI\google 內雙擊執行 啟動雲端清理工具.bat，或在終端機輸入 python server.py，接著使用瀏覽器開啟下方網址：

http://localhost:8080
步驟 02

前往 Google Cloud Console 建立專案

  1. 打開 Google Cloud Console 並登入您要清理空間的 Google 帳號。
  2. 點擊頁面上方的「選取專案」下拉選單，接著點擊右上角「新增專案（New Project）」。
  3. 輸入任意專案名稱（例如：MyDriveCleaner），點擊「建立」並等待右上角通知顯示建立完成後切換至該專案。
步驟 03

同時啟用 Google Drive API 與 Gmail API

在左側選單選擇「API 和服務」進入「程式庫（Library）」，分別搜尋並啟用下列兩個 API：

1. Google Drive API

負責讀取總容量配額、搜尋大檔案、判斷資料天數，以及移至垃圾桶與永久刪除檔案。

2. Gmail API

負責依附件大小與寄件天數搜尋信件、預估每封信件容量，以及批次清除舊信件。

步驟 04

設定 OAuth 同意畫面與加入「測試使用者」（極重要）

  1. 在左側選單開啟「Google Auth Platform」（或舊版「OAuth 同意畫面」），點擊開始設定。
  2. 使用者類型選擇「外部（External）」（一般個人 Gmail 帳號皆選此項；Google Workspace 公司帳號可視需求選內部）。
  3. 填寫應用程式名稱（例如 Drive and Gmail Cleaner）與支援電子郵件（填您自己的信箱），其餘聯絡資訊亦填您的信箱後儲存。
  4. 前往「目標對象（Audience）」分頁，在「測試使用者（Test users）」區塊點擊「新增使用者」，務必將您要登入清理的 Gmail 帳號加入清單。若漏掉這一步，登入時會出現 403 access_denied 錯誤。
  5. （選填）若於「資料存取（Data Access / Scopes）」畫面先加入權限，可加入下列兩項完整授權：
https://www.googleapis.com/auth/drive
https://mail.google.com/
步驟 05

建立「網頁應用程式」OAuth 用戶端 ID

  1. 在左側點擊「用戶端（Clients）」或「憑證（Credentials）」，點擊「建立用戶端（Create Client）」。
  2. 應用程式類型務必選擇「網頁應用程式（Web application）」。
  3. 在「已授權的 JavaScript 來源（Authorized JavaScript origins）」點擊「新增 URI」，填入下方網址（請注意結尾不可有斜線）：
http://localhost:8080

4. 「已授權的重新導向 URI」可留空。點擊建立後，將彈出視窗中的「用戶端編號（Client ID）」複製貼到本頁上方的輸入框並按下「儲存 Client ID」。

步驟 06

執行 Google 登入與勾選完整存取權限

  1. 點擊本頁的「立即登入 Google 帳號」按鈕，選擇您剛剛加入測試使用者的 Gmail 帳號。
  2. 因為此應用程式是您個人建立且處於測試狀態，Google 會顯示「Google 尚未驗證這個應用程式」警告畫面，請點擊左下角「進階（Advanced）」，再點擊「前往（應用程式名稱）（不安全）」。
  3. 在授權權限畫面中，請務必勾選允許存取「查看、編輯、建立及刪除您所有的 Google 雲端硬碟檔案」與「讀取、撰寫、傳送及永久刪除 Gmail 中的所有電子郵件」，最後按下「繼續」即完成登入。

常見登入與刪除問題排解

問題一：出現 Error 403 access_denied（存取權遭拒）

原因為您的 Google 帳號尚未加入「測試使用者」清單。請回到 Google Cloud Console 的「目標對象（Audience）」分頁，將當前登入的 Gmail 地址新增至 Test users 後重新整理網頁即可。

問題二：出現 Error 400 origin_mismatch

請檢查瀏覽器網址列是否為 http://localhost:8080（不可混用 127.0.0.1），並確認憑證的「已授權的 JavaScript 來源」填入完全相符且沒有結尾斜線。

問題三：Gmail 可以移至垃圾桶但無法「永久刪除」

Gmail API 的 batchDelete 必須取得完整權限 https://mail.google.com/。若登入授權畫面出現未勾選的核取方塊，請登出後重新登入並勾選全部權限項目。

問題四：操作約一小時後出現憑證過期（401）

瀏覽器端的 Google Access Token 預設有效期限為 3600 秒（一小時）。過期時系統會提示您，只需再次點擊右上角「登入 Google」按鈕重新授權即可接續作業。
